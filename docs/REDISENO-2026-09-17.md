## 4. Algoritmo — `RecomendacionServiceV2` simplificado

**Antes V1:** `JOIN (SELECT contenido_id, COUNT(*) FROM usuario_contenido)` como `pop`, `ORDER BY p.pop DESC`, `LIMIT 10` flat, pool por `JOIN` (solo con pop).

**Ahora V2** `src/infrastructure/services/RecomendacionServiceV2.ts:1`:

```ts
const LIMIT_POR_TIPO = 4;
const POOL_TOP = 50;
```

- **Afinidad se mantiene:** `SELECT c.tipo, COUNT(*) FROM usuario_contenido WHERE usuario_id=$1 GROUP BY tipo ORDER BY count DESC` y ordena `TIPOS` por afinidad (más consumido primero).
- **Pool por tipo:** `SELECT ... FROM contenidos c LEFT JOIN historial h ... WHERE c.tipo=$tipo AND NOT EXISTS (uc) AND NOT EXISTS (feedback no_me_gusta/ya_lo_vi) ORDER BY c.popularidad_externa DESC NULLS LAST LIMIT 50`
- **Shuffle:** `shuffle(pool).slice(0,4)` por tipo, fallback igual si `<4` (aunque con 90 y 83-89 no poseídos para `dani`, nunca hace falta). `yaAnadido = h.usuario_id IS NOT NULL`.
- Para usuario nuevo sin historial, misma query sin afinidad (orden por defecto), fallback populares globales por `popularidadExterna`.

Verificado: 5 reloads consecutivos para `dani` → cada tipo 4 títulos distintos, no solo orden distinto (ej. `pelicula: Zip Wire | La captura...` vs `pelicula: Mad Max | Rosebush...`), 16 tarjetas reales con `image.tmdb.org / images.igdb.com / i.scdn.co`.
